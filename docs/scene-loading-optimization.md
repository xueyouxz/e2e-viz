# 场景弱网加载优化

## 目标

- 加载期间保持最终布局，避免页面结构跳变。
- 并行下载元数据和首帧，首帧提交后再进入就绪状态。
- 限制后台预取并发，并优先处理用户请求的帧。
- 缓冲范围只统计已经解析并进入缓存的连续帧。

## 已实现的加载链路

```text
message_index.json
        ↓
metadata.glb ───────────┐
首帧 frame-0.bin ───────┼─ 并行下载
        ↓               ↓
解析元数据 → 解析首帧 → 提交初始场景 → 进入就绪状态
```

- `SceneLoader` 在读取目录后并行请求元数据和首帧。
- `MessageParser` 复用同一套 Stream payload 解析逻辑，帧消息优先在 Worker 中解析。
- `SceneManager.start()` 等待元数据和首帧完成，加载失败会直接进入错误状态。
- `SceneViewer` 始终保留画布和面板布局，就绪前显示统一的 `Loading` 覆盖层。
- 后台预取改为最多 2 个并发任务；用户指定帧会从等待队列提升为高优先级。
- 缓冲条只延伸到已下载、已解析并进入缓存的连续帧。

## 后续优化优先级

1. 将 `SceneViewer` 的 Three.js / R3F 依赖拆为更细的异步块。当前构建产物约 302 KiB gzip，是低带宽下进入场景页前的固定等待。
2. 服务端为 `.glb` 和帧文件提供 Brotli、长期缓存和 CDN 边缘缓存。
3. 为帧文件提供服务端生成的轻量预览（低分辨率相机图或 BEV 摘要），使首帧前可渐进展示场景内容，而非只展示状态。
4. 后续加载优化先检查请求优先级、并发上限、缓存窗口、取消链路和 Blob URL 所有权，不在应用内增加持续性能采集或发布数值门禁。
