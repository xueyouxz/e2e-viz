# 场景弱网加载优化

## 现状问题

- `SceneViewer` 在元数据完成前直接返回纯文本，加载态与最终三栏画布布局不同，网络慢时会出现明显跳变。
- 首帧数据虽然与 `metadata.glb` 并行请求，但页面没有下载、解析和就绪状态，用户只能看到无反馈的等待。
- `prefetchAround()` 会安排当前窗口内的后台请求。弱网下必须保持并发限制和用户请求优先级，避免延后用户真正要看的帧。
- 时间轴将“请求中”也标记为缓冲完成，无法准确反映可播放范围。

## 已实现的加载链路

```text
message_index.json
        ↓
metadata.glb ───────────┐
首帧 frame-0.bin ───────┼─ 并行下载
        ↓               ↓
解析元数据 → 保持最终布局骨架 → 解析首帧 → 渲染 Canvas
        ↓
显示下载字节、阶段和进度；未知 Content-Length 时使用不确定进度条
```

- `SceneRepository` 使用 `ReadableStream` 读取目录、元数据和首帧，向 `SceneSession` 发布字节进度。
- `SceneLoadingOverlay` 覆盖在稳定的布局骨架上：下载场景目录、场景结构、首帧、解析与就绪五个阶段均可见。
- 元数据完成后立即创建画布和面板；首帧未完成前用半透明覆盖层避免空白画布。
- 后台预取改为最多 2 个并发任务；用户指定帧会从等待队列提升为高优先级。
- 缓冲条只延伸到已下载、已解析并进入缓存的连续帧。

## 后续优化优先级

1. 将 `SceneViewer` 的 Three.js / R3F 依赖拆为更细的异步块。当前构建产物约 302 KiB gzip，是低带宽下进入场景页前的固定等待。
2. 服务端为 `.glb` 和帧文件提供 Brotli、长期缓存和 CDN 边缘缓存；同时保证 `Content-Length` 可见，进度条才可显示准确百分比。
3. 为帧文件提供服务端生成的轻量预览（低分辨率相机图或 BEV 摘要），使首帧前可渐进展示场景内容，而非只展示状态。
4. 在线上真实网络档位（例如 3G / 1 Mbps / 高延迟）采集首帧可交互时间、首帧渲染时间、卡顿率和预取命中率，作为发布阈值。
